## `06` — HOW I WORK

```text
PROBLEM
  │
  ├── Understand the requirement
  ├── Break it into smaller pieces
  ├── Design data + business logic
  ├── Implement the smallest correct solution
  ├── Test edge cases
  ├── Debug the actual failure
  └── Ship + iterate
```

| Principle | Meaning |
|---|---|
| **Simple > Clever** | Complexity needs a reason |
| **Correctness first** | A fast wrong system is still wrong |
| **Readable code** | Future-you is another developer |
| **Root-cause debugging** | Don't patch symptoms blindly |
| **Production mindset** | Validation, errors and maintainability matter |
